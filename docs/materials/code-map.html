01

システム構成

Next.js のアプリが2つ（公開用 webapp と管理用 admin）、データは Supabase に集約されています。admin で書きこんだデータを webapp が読み、admin は更新のたびに webapp のキャッシュを無効化します。

02

コンテキストマップ

src/server/contexts/ の下は業務ごとの Bounded Context に分かれています。コンテキスト同士は直接 import せず、共通のものは shared に置きます。webapp と admin の間でコードは共有せず、データベースを介してつながります。

03

レイヤー構成

各コンテキストの中は4層です。矢印の向きにしか import できません。presentation が実装クラスを new して usecase に渡す、シンプルな DI です。

04

リクエストの流れ

読み取り（webapp の表示）と書きこみ（admin の更新）で通る経路が決まっています。新しい機能もこの型にはめて書きます。

05

データモデル

スキーマは prisma/schema.prisma の1ファイルです。政治資金側と調研費側で、ほぼ独立した2つのまとまりになっています。

06

機能の逆引き

画面や API ごとに、関係するファイルをレイヤー順に並べています。機能名・URL・ファイル名のどれでも検索できます。
