02

コンテキストとレイヤー

業務ごとにフォルダを分けている。コンテキストどうしは直接 import せず、共通の処理は shared/ に置く。webapp と admin はコードを共有せず、同じデータベースでつながっている。

コンテキスト

  • webapp/src/server/contexts/
    • public-finance/政治団体の集計・サンキー図・貸借対照表、取引一覧・CSV
    • research-fund/公開済みの調研費の表示、領収書の署名 URL・CSV
    • shared/Prisma クライアント、共通モデル
  • admin/src/server/contexts/
    • auth/ログイン、ユーザー管理、認可ガード
    • data-import/MF CSV の取りこみ、環境間の同期、取引の削除
    • report/報告書 XML、取引先・寄附者、AI 住所検索
    • research-fund/領収書の AI 読み取り、仕訳の確認・公開、提出用 CSV
    • shared/政治団体・議員・残高・取引、webapp のキャッシュ無効化、同期用 JSON の書き出し

各コンテキストの中（レイヤー）

  • {webapp,admin}/src/
    • app/ルーティング（page.tsx・route.ts）
    • client/"use client" の部品とヘルパー
    • server/contexts/{コンテキスト}/
      • presentation/
        • loaders/データ取得・unstable_cache
        • actions/"use server"・revalidate
      • application/
        • usecases/1 クラス 1 操作。execute だけ
        • services/組み立て・スコアリング
      • domain/
        • models/1 つのエンティティのルール
        • services/複数にまたがるルール
        • repositories/インターフェースだけ
      • infrastructure/
        • repositories/prisma-*.repository.ts
        • llm/ storage/ mf/ donor-csv/外部サービスとの接続

import できる向き

app/→presentation→application→domain←infrastructure
  • import は矢印の向きだけ逆向きは dependency-cruiser で CI が落ちる
  • infrastructure は domain のインターフェースを実装presentation で new して usecase に渡す（DI コンテナなし）
  • client/ から server へは型と純粋関数だけ"use client" は必要なときだけ

横断的な仕組み

  • 認証・メンテナンスadmin/src/proxy.ts
  • 操作の権限チェックauth/presentation/loaders/require-auth.ts
  • 操作中の団体・議員shared/presentation/loaders/load-current-organization-target.ts
  • 公開サイトのキャッシュwebapp/…/loaders/constants.ts
  • キャッシュを消すshared/infrastructure/services/webapp-cache-invalidator.ts
  • DB の設計図prisma/schema.prisma
  • Prisma の接続shared/infrastructure/prisma.ts
  • AI の呼び出し*/infrastructure/llm/
  • エラーの形*/domain/types/validation.ts
  • 報告書 XML の仕様docs/reference/report-format.md
  • 依存ルールの検査.dependency-cruiser.cjs
  • usecase の形の検査scripts/check-usecase-shape.mjs
  • SEO（sitemap）webapp/src/app/sitemap.ts
  • テスト{webapp,admin}/tests/ ・ e2e/
