1

何をするアプリ？

政治団体は、毎年のお金の出入りを「政治資金収支報告書」という書類にまとめて国に出す決まりがあります。でもその書類は数字の表ばかりで、ふつうの人が読むのは大変です。

そこでこのアプリは、団体がふだん使っている会計ソフトのデータを取り込み、お金の流れを図やグラフにして公開します。さらに、国に出す報告書のデータ（XMLという形式のファイル）を作るお手伝いもします。

最近は、国会議員に支給される「調研費（ちょうけんひ）」の使い道を、領収書つきで公開する機能も加わりました（6章）。

このアプリは、じつは2つのWebアプリのセットです。

webapp/ ・ だれでも見られる

公開サイト

  • 収入と支出の流れ図（サンキー図）
  • 月ごとの収支グラフ
  • 貸借対照表（いま持っている財産と借金）
  • 取引の一覧表とCSVダウンロード
  • 議員ごとの調研費の使い道と領収書
admin/ ・ 団体のスタッフだけ

管理画面

  • ログイン（パスワードで本人確認）
  • 会計ソフトのCSVファイルを取り込む
  • 取引先や寄附した人の情報を整理する
  • 政治資金報告書のXMLを作る
  • 領収書をAIで読み取って、調研費の帳簿を作る
ポイント見る人用と管理する人用を分けておくと、公開サイトには「見せる機能」しかないので、だれかが勝手にデータを書きかえる入り口ができにくくなります。
2

全体の地図

アプリを動かしているのは、いくつかの「建物」です。インターネットの向こうにあるコンピューター（サーバー）が、それぞれ別の仕事をしています。

大事なのは、データベースが1つだけということです。管理画面で書きこんだデータを、公開サイトが読みだして表示します。黒板に先生が書いた内容を、クラス全員が見るのに似ています。

3

プログラムの役割分担

プログラムのファイルは数百個あります。全部がバラバラに好き勝手なことをすると、どこを直せばいいのか分からなくなります。そこでこのアプリでは、レストランの役割分担のように、ファイルを4つの「層（レイヤー）」に分けています。これをレイヤードアーキテクチャと呼びます。

ホール係presentation/
お客さん（画面）から注文を受けて、できた料理を運ぶ。ログインしているかのチェックもここ。 例：loaders/ はデータを取ってくる係、actions/ は「保存」ボタンなどの操作を受ける係
↓ 注文を伝える
店長application/
注文を見て「まず倉庫から材料を出して、次にレシピどおり作って…」と段取りを決める。 例：usecases/preview-mf-csv-usecase.ts（CSVを読んで確認画面用のデータを作る段取り）
↓ 段取りにそって
レシピ・ルールdomain/
このお店ならではの決まりごと。「寄附は1人いくらまで」「この科目は収入」など、政治資金ならではのルールが書かれている。 例：services/sankey-data-builder.ts（流れ図の形にデータを組み立てる）
↓ 材料をたのむ
倉庫係infrastructure/
データベースや外のサービス（AIなど）と実際にやりとりする。倉庫の場所が変わっても、ここだけ直せばOK。 例：repositories/prisma-transaction.repository.ts（取引データを出し入れする）

さらに、仕事の内容ごとに「部署」も分けています。これをBounded Context（境界づけられたコンテキスト）と呼びます。

部署の名前アプリ担当している仕事
public-finance公開サイト政治資金のデータを集計して、グラフ用に整える
research-fund公開サイト公開された調研費を、議員ごとのページに表示する
data-import管理画面会計ソフトのCSVを読みこみ、確認してから保存する
report管理画面取引先・寄附者の管理と、報告書XMLの作成
research-fund管理画面領収書の読み取り、調研費の帳簿づくり、提出用CSVと公開
auth管理画面ログインと、だれが何をしてよいかの管理
shared共通どの部署も使う道具（データベースへの接続など）
なぜこうするの？「グラフの色がおかしい」ならホール係、「集計の計算がおかしい」ならレシピ、というように、問題が起きたときに探す場所をしぼれるからです。たくさんの人が同時に開発しても、ぶつかりにくくなります。
4

データを登録する流れ

団体のスタッフが、会計ソフトから出したCSVファイルを管理画面にアップロードしたとき、裏側では次のことが順番に起きています。

  1. ログインしているか確認 まず「この人は本当に団体のスタッフ？」をチェックします。ログインしていなければ、ここで止まります。 auth / require-auth.ts ・ proxy.ts
  2. 文字化けを直して読みこむ 会計ソフトのCSVは、古い日本語の文字コード（Shift_JIS）で保存されていることがあります。そのままだと文字化けするので、変換してから1行ずつ読みます。 data-import / encoding-converter.ts（iconv-lite を使用）
  3. アプリ用の形に変換 CSVの1行（日付・勘定科目・金額…）を、アプリが扱いやすい「取引」の形に変えます。「これは収入？支出？」もここで判定します。 data-import / mf-record-converter.ts
  4. おかしなデータがないか点検 金額が空っぽ、日付が変、すでに登録済み…などを調べ、問題のある行に印をつけます。 data-import / transaction-validator.ts
  5. 確認画面（プレビュー）を表示 いきなり保存せず、「この内容で登録しますか？」と見せます。人間が目で確かめてから決められます。
  6. データベースに保存 「登録」ボタンが押されたら、正しい行だけをデータベースに書きこみます。 data-import / upload-csv.ts → save-preview-transactions-usecase.ts
  7. 公開サイトに「更新したよ」と合図 公開サイトに合言葉（トークン）つきでお知らせを送ります。公開サイトは古いデータの控えを捨てて、次から新しいデータを表示します。 shared / webapp-cache-invalidator.ts → webapp /api/refresh
5

グラフが表示される流れ

市民がスマホで公開サイトを開いたときの流れです。URLは /o/団体名/2026 のような形になっています。

  1. URLから「どの団体の、何年分か」を読みとる Next.js の App Router が、URLの形に合わせてページのプログラムを選びます。 webapp/src/app/o/[slug]/[year]/page.tsx
  2. まず「控え（キャッシュ）」を見る 同じページを見る人は大勢います。毎回データベースで計算するとおそくなるので、一度作った結果を控えておき、本番では最大1時間使い回します。 load-top-page-data.ts（unstable_cache ・ 3600秒）
  3. 控えがなければ、データベースから集計 取引を月ごとに合計したり、収入→支出の流れ図用に組み立てたりします。この計算はすべてサーバー側でやります。 usecases/get-sankey-aggregation-usecase.ts など
  4. サーバーでHTMLを作って送る React のサーバーコンポーネントが、ページの大部分を完成させてから送ります。スマホ側の仕事が減るので、表示が速くなります。
  5. スマホの中でグラフを描く 動くグラフ（マウスを乗せると数字が出るなど）だけは、スマホやパソコンの中で描きます。流れ図は Nivo、月別グラフは ApexCharts という道具を使っています。 client/components/top-page/features/charts/
サーバーとブラウザの分担重い計算や秘密の情報（データベースのパスワードなど）はサーバーに置き、ブラウザには「見た目」と「さわったときの反応」だけをまかせる、というのがこのアプリの基本方針です。
6

調研費と領収書AI

国会議員には、政治資金とは別に「調査研究広報滞在費（調研費）」というお金が毎月支給されます。このお金の使い道を、だれでも確かめられるように公開するのが新しい機能です。どんなお店で何に使ったかを、領収書の画像といっしょに見せます。

領収書は1年で何百枚にもなります。全部を人が手で打ちこむのは大変なので、ここでAIが活躍します。

  1. 領収書をアップロード 議員事務所のスタッフが、領収書の写真やPDFを管理画面に入れます。ファイルは Supabase Storage（ファイル置き場）に保存されます。 research-fund / create-scan-batch-usecase.ts
  2. AI（Claude）が領収書を読む 画像を見て、日付・お店の名前・金額・品目を取り出します。答えは決まった形（JSON）で返してもらい、形がおかしければはじきます。 vercel-ai-receipt-extraction-gateway.ts
  3. 仕訳（しわけ）の下書きができる 読み取った内容から「何のために、いくら使ったか」を記録した帳簿の1行（仕訳）を自動で作ります。支払先のお店も、名前から自動で結びつけます。 scan-journal-builder.ts ・ issuer-payee-matcher.ts
  4. 人がチェックして「確認済み」に AIはまちがえることがあります。スタッフが1件ずつ見て、直してから確認済みにします。読みまちがいが多いときは、AIへの指示文（プロンプト）を事務所ごとに調整することもできます。
  5. 公開する ＆ 提出用のファイルを作る 確認済みの仕訳を「公開済み」にすると、公開サイトの議員ページ（/p/議員名/年）に出ます。衆議院・参議院の担当課に出すためのCSVもここから作れます。
個人情報への気くばり仕訳は「下書き → 確認済み → 公開済み」の順にしか進めないルールが、プログラムの「レシピ（domain）」の層に書かれています。また、支払先の住所などは公開サイトには出さず、提出用のファイルにだけ入れます。

データベースの中身

データベースは、Excelのシートがたくさん入ったファイルのようなものです。シート1枚をテーブルと呼びます。主なテーブルはこちら。

テーブル入っているものたとえると
PoliticalOrganization政治団体の名前やURL用の名前クラス名簿
Transaction1件1件のお金の出入り（日付・科目・金額・説明）家計簿の1行
BalanceSnapshotある日の時点での残高通帳の残高ページ
Counterpartお金を払った相手（会社など）と住所お店の連絡先リスト
Donor寄附をしてくれた人・団体お礼状の宛名リスト
OrganizationReportProfile報告書の表紙に書く代表者などの情報書類の表紙
Politician国会議員の名前やURL用の名前議員の名簿
ResearchFundBook議員1人・1年分の調研費の帳簿1年分の家計簿ノート
ResearchFundDocumentアップロードされた領収書ノートに貼ったレシート
ResearchFundJournalEntry調研費の使い道1件（下書き・確認済み・公開済み）家計簿の1行
User / Tenant管理画面にログインできる人と、所属職員室の名簿

ここに出したのは一部で、全部で20以上のテーブルがあります。テーブルどうしは線でつながっています。たとえば「取引」には「どの団体のものか」が書かれていて、団体を消すとその団体の取引もまとめて消えるように設定されています。この設計図は prisma/schema.prisma という1つのファイルに書かれています。

9

ミスを防ぐしくみ

お金のデータをあつかうので、まちがいは許されません。そこで、プログラムを変更するたびに、機械が自動で何重にもチェックします。

チェック道具何を調べる？
小さなテストJest「この計算に1000と2000を入れたら3000になる？」のように、部品ごとに答え合わせ
通しのテストPlaywrightロボットが本物のブラウザを操作して、ログイン→アップロード→表示…を試す
型チェックtscTypeScript のルール違反がないか
書き方チェックBiome書き方の統一と、あやしい書き方の発見
使われていないものknipだれも使っていないファイルや道具が残っていないか
役割分担のルールdependency-cruiser3章の「層」のルールを破って、ホール係が直接倉庫に行っていないか
店長の仕事の形check:usecase-shape店長（usecase）1人が1つの仕事だけを受けもっているか

これらは pnpm verify という1つの命令でまとめて実行され、GitHubに送る前（push前）とGitHub上（CI）の両方で自動的に動きます。1つでも失敗すると、変更は取りこまれません。

さらに、すべての変更は AI のレビュー係（CodeRabbit）にもチェックされます。一部の決まった作業は、AIが自分でプログラムを書いて提案するしくみも動いています。最後に本番のサイトへ出すボタンを押すのは人間です。

オープンソースこのアプリのプログラムは GitHub で全部公開されていて（AGPL-3.0ライセンス）、だれでも読めます。「お金の流れを透明にする」アプリ自身も、中身が透明になっています。

用語集

サーバー
インターネットの向こうで、たのまれた仕事をするコンピューター。
ブラウザ
ChromeやSafariなど、Webページを見るためのアプリ。
データベース
データを整理して保存し、すばやく取りだせるようにした入れ物。
CSV
表のデータを「,（カンマ）」で区切って書いたテキストファイル。Excelでも開ける。
XML
<名前>山田</名前> のように、タグでデータをはさんで書くファイル形式。報告書の提出に使う。
キャッシュ
一度作った結果の控え。同じものをまた作らずにすむので速くなる。
ライブラリ
だれかが作って公開している、再利用できるプログラムの部品。
トークン
「本物のお知らせです」と証明するための合言葉。
サンキー図
線の太さで量を表しながら、どこからどこへ流れたかを描く図。
調研費
調査研究広報滞在費。国会議員に毎月支給される、調査や広報などのためのお金。
仕訳（しわけ）
「いつ・何に・いくら」を帳簿に書く1行のこと。
プロンプト
AIへの指示文。書き方しだいでAIの答えが変わる。
CI
変更が届くたびに、自動でテストやチェックを走らせる仕組み。
